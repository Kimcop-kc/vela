# 长篇小说回归样本集

用途：给「优化到底有没有让生成质量变好」提供一把尺子。每次改动写完稿流程、审稿、事实库、上下文组装之后，用这里的样本跑一遍对照，看**引入的新错误**，而不只是看「修好了几个」。

## 目录

- `cases/*.json`：每个样本一个文件，包含该场景的章纲、前情、已确认事实、必须出现/不许出现的内容、人工核对清单，以及用于**确定性检测**的两段示例文本（`excerpts.bad` 应当被检出问题，`excerpts.clean` 不应被检出问题）。
- 确定性部分由 `src/services/__tests__/novel-regression.test.ts` 在 CI 里跑：它只使用本地规则（AI 痕迹检测），不调用模型。

## 怎么用（本地手动部分）

1. 在 Vela 里新建一个测试项目，按 `cases/*.json` 里的 `blueprint` 建章节蓝图，`precedingSummary` 与 `canonFacts` 填进设定/事实库。
2. 用同一组模型配置跑「写稿」（以及需要的审稿、去 AI 味），把生成的正文导出或复制出来。
3. 对照该样本的 `mustInclude` / `mustNotInclude` / `manualChecks` 逐条核对，记录下表指标：

| 指标 | 本次 | 上次 | 备注 |
|---|---|---|---|
| 设定错误数 | | | |
| 剧情矛盾数 | | | |
| 人物认知错误数 | | | |
| 大纲遗漏数 | | | |
| 物品状态错误数 | | | |
| 时间线错误数 | | | |
| 检索到的无关资料数 | | | |
| 需要人工改动的次数 | | | |
| 改动后新引入的错误数 | | | |

4. 结论由人判断：**这些指标是给对照用的，不自动判定通过或失败。**

## 为什么不做成全自动

语义层面的判断（人物是否知道了不该知道的事、情节是否合理）需要模型参与，而 CI 既没有模型 key、也不该为此付费。所以：**能机器判定的（文风痕迹、格式类问题）进 CI；需要理解的走人工清单。**
