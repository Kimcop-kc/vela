## 1. 专注模式（任务书 5.4）

### 1.1 关键设计：布局状态，不是新页面

任务书明确要求「专注模式应是布局状态，而不是另开一个会丢失编辑上下文的页面」。因此实现上：

- **只往 `layout-store` 加字段，完全不碰 `editor-store`** —— 编辑器实例、标签页、光标、滚动位置、未保存内容都不参与，从结构上就不可能「清空编辑器状态」；
- 快照 `FocusSnapshot` 只含 5 个**布局**字段：`sidebarOpen` / `aiPanelOpen` / `bottomPanelOpen` / `bottomDock` / `autoCollapsed`。这条边界有单测锁住（往快照里塞内容相关字段会让用例失败）。

### 1.2 隐藏什么、保留什么

| 区域 | 专注模式下 |
|---|---|
| 左侧工具窗口栏（44px 图标条） | **隐藏** |
| 右侧工具窗口栏 | **隐藏** |
| 侧栏 / 右栏 / 底部面板 | 收起（`enterFocusMode` 直接置 `false`） |
| 标题栏 | **保留**（含窗口控制，且专注模式开关本身在这里） |
| 标签栏、编辑区 | **保留** |
| 字数 / dirty / 保存信息栏 | **保留** |
| 状态栏（22px） | **保留** |

两点说明：

- **标签栏保留**：任务书 6.1 把「标签栏 / 当前章节标题」列为编辑区布局的一部分，且 dirty 指示与关闭确认挂在标签上，隐藏它反而增加丢稿风险。
- **状态栏保留**：它只有 22px，且承载 AI 任务进度与当前模型；专注模式要挤掉的是与正文**争宽度**的竖栏，不是底部一条信息带。这一条属主动取舍，如与预期不符可单独调整。

### 1.3 三处容易写错的边界（都有单测）

1. **幂等进入**。`enterFocusMode` 若已存在快照就直接返回。否则第二次进入会把「已经全 false 的空布局」当成快照存下来，退出后用户面对的是一个被收干净的工作台。
2. **用户主动开面板 = 手动接管**。所有「打开面板」的动作（`toggleSidebar` / `setSidebarOpen(true)` / `setSidebarView` / `toggleAIPanel` / `setAIPanelOpen(true)` / `openRightPanel` / `toggleBottomPanel` / `setBottomTab` / `openBottomTab` / `setBottomDock` / `sendToStyleAnalysis`）都会先调 `abandonFocusSnapshot()` —— **只丢快照、不改面板状态**。这样既不会出现「专注模式开着但面板也开着」的矛盾态，也不会在用户刚打开面板后又被退出逻辑关回去。
3. **窄窗口自动折叠让路**。`useAutoCollapseOnNarrowWindow` 在专注模式期间**只更新自己的 `narrow` 记账、不动布局**。否则窗口一变宽，它会去「恢复被自动收起的面板」，直接把专注模式顶掉。进入专注模式时也会清空 `autoCollapsed`，避免两套恢复逻辑互相覆盖。

### 1.4 快捷键为什么不受「可编辑元素豁免」保护

`App.tsx` 里 `⌘+N` / `⌘+O` 前有一道 `isEditableTarget(e)` 早退，避免写作途中被弹窗打断。但专注模式**必须放在这道早退之前**：最典型的使用场景就是光标正在正文里，若在这里让回给输入，专注模式在写作时反而按不动。

键位选了 `⌘/Ctrl+⇧+F`（Focus）。全库现有全局键位只有 `⌘+N/O`、`⌘+=/-/0`、`⌘+W`、编辑器内的 `⌘+F/S`，无冲突；`F11` 因可能与 Electron/系统全屏冲突而弃用。

### 1.5 开关的可见性

标题栏按钮开启时用 `--color-accent` + `--color-accent-soft` 底色标出，避免用户忘了自己为什么看不到侧栏。图标在 `Maximize2` / `Minimize2` 间切换，并带 `aria-pressed`。

## 2. 阅读设置（任务书 6.4）

### 2.1 四项设置与默认值

| 设置 | 范围 | 默认 | 默认值的来历 |
|---|---|---|---|
| 字号 | 14–24px | **16px** | 改造前 `CodeMirrorEditor` 里 `mode === 'prose' ? "16px"` |
| 行高 | 1.4–2.4 | **1.8** | 改造前 `.cm-content` 的 `lineHeight: "1.8"` |
| 纸面宽度 | 560–1200px | **800px** | 改造前 `.cm-content` 的 `maxWidth: "800px"` |
| 段落间距 | 0–1.5em | **0** | 改造前 `.cm-line` 的 `padding: "0"` |

**四个默认值刻意等于改造前的硬编码值**，所以「装上即与旧版渲染完全一致」，老用户升级后排版不会静默变化。这条有单测锁住。

「字体」这一项**没有新增字段**：任务书 6.4 要求的字体调整由既有的 `theme-store.writingFont`（→ `--font-writing`）承担，阶段 B 已确认它是唯一真源。

### 2.2 作用域：CSS 变量注入编辑画布

沿用阶段 B 建立的机制：变量挂在 `EditorArea` 的「编辑区主体」容器上，靠自定义属性的子树继承限定作用域，**不挂 `html` / `body`**。`CodeMirrorEditor` 侧读取时一律带兜底：

```ts
maxWidth: "var(--editor-max-width, 800px)",
lineHeight: "var(--editor-line-height, 1.8)",
".cm-line": { padding: "0 0 var(--editor-paragraph-spacing, 0) 0" },
```

兜底值与各自的 `*_DEFAULT` 常量一一对应，即便编辑器将来被渲染到该容器之外也不会跑版。

### 2.3 段落间距的实现原理

CodeMirror 6 里**一个 `.cm-line` 就是一个文档行**（软换行在同一行元素内部由 CSS 完成），而中文小说的排版习惯是一段一行。因此给 `.cm-line` 加 `padding-bottom` 就等于「段落间距」，不会误伤同一段内的换行。改动前该规则是 `padding: "0"`，与默认值 0 完全一致。

### 2.4 防御性处理

四个 setter 共用 `clampNumber(value, min, max, digits)`：先 `Number.isFinite` 过滤（非有限值直接忽略，不写状态），再钳制、再按位取整（字号 / 纸面宽度取整，行高 / 段落间距保留一位小数）。原因同阶段 B：这些值会被拼进 CSS 变量（`NaN` 会让整条声明失效）**并写入 localStorage**，一旦污染就会持久化。

### 2.5 设置界面

`EditorSection` 里新增「阅读设置」分组，四项复用新抽出的 `SliderRow` 组件（标签 + 说明 + 实时读数 + 滑杆），避免同一套版式抄四遍。中 / 英 / 俄三语各补 7 个键。

## 3. 核查后未改动的部分（如实说明）

任务书第六节里，以下三条经核查**现状已满足或属回归项**，本阶段未动代码：

- **6.1 编辑区布局**：标签栏、当前章节名、正文区、保存状态、字数统计、常用操作工具栏均已存在（`ProseEditorWrapper` 含文件名 + 字数 + dirty 圆点 + 保存按钮；`DraftEditor` 含修稿 / 审稿 / 定稿工具栏）。任务书要求的「正文应获得足够宽度，不要让大块统计卡片挤压写作空间」——现状本就没有统计卡片，且本阶段通过**专注模式**与**纸面宽度设置**进一步保证。
- **6.2 编辑器操作**：新建 / 打开 / 编辑 / 保存 / 撤销重做 / 标签切换 / 版本历史 / 重写 / 精修 / 审稿 / 选区操作 / 上下文菜单 / 导出均为既有能力，属回归范围而非改造范围。
- **6.3 AI 操作**：任务书明确要求「不要为了 UI 美化重写现有 AI 服务、提示词或模型调用逻辑」，因此仅做核查：主操作与次要操作的层级、选区作用范围提示、生成结果走原业务服务等现状均已满足。

**dirty 保护回归**：`EditorArea.tsx` 的 `⌘+W` 关闭（`t.dirty → setCloseConfirm`）、`tryCloseTab`、`tryBatchClose` 三条路径经核查完好，且本阶段改动未触碰 `editor-store`，不存在交互影响。单条与批量的关闭确认弹窗均保留。

## 5. 未做与原因

- **`⌘+⇧+F` 未纳入任何快捷键注册表**：全库没有 UI 快捷键注册表（`src/services/workflows/commands/` 是 AI 工作流命令，不是 UI 命令），因此沿用了现状的「在组件里直接 `addEventListener`」写法。若后续要统一键位管理，属独立批次。
- **专注模式未持久化**：它是会话内的临时布局状态，刷新后回到常规布局。任务书未要求持久化，且持久化会让用户下次启动时面对一个「不知道为什么少了两栏」的界面。
- **阶段 B 记录的既有待办**（`FeatureTour` 的 `z-[10000..10002]`、Tailwind 调色板类、`novel-editor.css` 的 Tiptap 遗留规则）本阶段未处置，仍挂账。
